# 要件 — ちいさな終着駅

このファイルは「何を作るか」をまとめたものです。指示書の内容を整理し、作業中に置いた
**仮定**(はっきり決まっていないことを、とりあえずこう決めたもの)も記録します。

## 1. ゲームの概要

| 項目 | 内容 |
|---|---|
| タイトル | ちいさな終着駅 |
| ジャンル | 線路パズル + ミニチュア風の町づくり + 列車・駅・住民のコレクション |
| 対応 | Android(Google Play)、iOS(App Store) |
| 画面 | 縦画面 |
| 1 ステージ | 約 1〜3 分 |
| ネット | オフラインで主要な機能が遊べる。アカウント登録なし |
| 保存 | 進行状況は端末の中に保存する |
| コンセプト | 小さな列車を正しい線路へ導き、クリアするたびに終着駅の町が育っていく |

競争や時間制限は中心にせず、落ち着いた雰囲気で遊べることを大切にします。

## 2. 作らないもの(初期リリース)

- オンライン対戦、チャット、ランキング
- サーバーの運用、ユーザーアカウント
- 住民の複雑な AI、交通シミュレーション、建物の中の探索
- 自由度の高い都市建設(配置できる場所はあらかじめ決めておく)

## 3. 機能の要件

### 3.1 パズル
- 線路タイルをタップすると時計回りに 90° 回る
- 「1手戻す」「リセット」ができる
- 「出発」で列車が走り、目的地の駅に着けばクリア
- 進めない・盤面の外へ出る・目的地以外の駅に着く・ループする場合は止めて失敗を表示
- 判定(経路の検証)は先に計算し、アニメーションはその結果を再生するだけにする
- 盤面は 5×5 を基本に、後半は 6×6・7×7 も使えるようにする
- 星 1〜3 の評価(ステージごとの基準手数で決める)。再挑戦で最高評価は下がらない

### 3.2 ステージ
- ステージはコードに書かず、JSON(データの書き方の一種)で管理する
- 読みこむときに中身を検査し、おかしなデータは飛ばす(アプリは止まらない)
- すべてのステージが解けることを自動テストで確かめる。同じ盤面の使い回しはしない
- まず 10 ステージ → 初期リリースで合計 50 ステージ

### 3.3 町づくり・コレクション(Phase 2)
- クリア報酬のコインで建物・装飾を開放し、決まった場所に配置する
- コインが不正な値(マイナス・上限超え)にならない
- 列車・駅舎・建物・装飾・住民を集める。ID・名前・説明文・獲得状況を持つ

### 3.4 画面
タイトル / ステージ選択 / パズル / クリア / 町 / コレクション / 設定(詳しくは game_design.md)。

### 3.5 収益化(Phase 3。基本ゲームの完成後)
- リワード広告(任意で見る広告)を優先。インタースティシャル広告(画面の切り替わりに出る
  広告)は頻度を慎重に決める
- 広告削除・追加ステージ・見た目のパックをアプリ内課金で
- パズル操作中・列車の走行中には広告を出さない。広告が読めなくてもゲームは止まらない
- 購入の成功・失敗・保留・復元・重複防止に対応する

### 3.6 品質
- 小さな画面から大きな画面まで表示が崩れない
- 連続タップ・走行中の操作・アプリの一時停止と復帰で状態が壊れない
- 秘密鍵や API キーをリポジトリに入れない

## 5. 仮定(作業を止めないために置いたもの)

| # | 仮定 | 理由・あとで見直す点 |
|---|---|---|
| A1 | 既存リポジトリの中に `chiisana_shuchakueki/` フォルダを作り、そこを Flutter プロジェクトにする | 既存の「霧笛荘事件」のファイルを一切変えないため。別リポジトリに分けたい場合はフォルダごと移せる |
| A2 | アプリ ID は仮で `com.example.chiisana_shuchakueki` | 公開前に持ち主のドメインなどで一意の ID に変える必要がある(release_checklist.md) |
| A3 | 1 回のタップ = 1 手。「1手戻す」は手数を 1 減らす | 星の基準(★3)はソルバーが求めた最少手数ちょうど、★2 は最少手数 + max(2, 最少手数の半分) |
| A4 | T字線路は「直進できれば直進、突き当たりでは右へ曲がる」 | 初期ステージでは使わない。分岐の切り替えは今後の拡張 |
| A5 | 十字線路は回しても形が変わらないので「回せないタイル」扱い | タップしても手数が増えない |
| A6 | 駅は回せない。出発駅の向き = 列車が出ていく向き | |
| A7 | (Phase 1 では保存なし)→ Phase 2 で端末への保存を実装済み | 機種変更での引きつぎはまだない |
| A8 | クリア報酬:毎回 `10 + 難易度×5` コイン、初回だけ `20 + 難易度×10` コインを追加 | 町の建物の値段が決まったら調整する |
| A9 | ヒントは今は回数制限なし・星への影響なし | Phase 3 でリワード広告と組み合わせるか検討 |
| A10 | 絵は外部素材を使わず、自作の SVG から書き出した PNG/JPEG(`tool/art/` → `assets/images/`) | 持ち主の指摘(「チープで商品化できない」)を受けて、図形の組み合わせから、質感・影・光沢を描きこんだ絵に作り直した |
| A21 | 文字は Zen Maru Gothic(OFL)を、使う文字だけに絞って同梱(約 800KB) | 温かみのある丸ゴシック。端末によって字形が変わらない |
| A11 | 文字の大きさの設定は最大 1.3 倍までに抑える | 大きくしすぎると盤面やボタンがはみ出すため |
| A12 | ステージ 1〜3 は手作り、ほかの 47 ステージは自動生成した盤面を固定して収録 | 生成は開発用の道具(`tool/`)で行い、結果の JSON を収録する。アプリ内でランダム生成はしない |
| A13 | ワールドの開放:前のワールドの最後をクリア + 合計の星 15 / 35 / 55 / 75 | ★2 ばかりでも少し ★3 を取れば進める程度。遊んでもらって調整する |
| A14 | 一度買った建物・装飾は、いくつの区画にでも置ける。片づけは無料でコインは戻らない | 「同じ木を並べたい」に応えるため。コインが増える抜け道を作らない |
| A15 | 住民・駅舎・列車は条件を満たすと自動で手に入り、一度手に入れたらなくならない | 建物を片づけても住民は帰らない |
| A16 | 効果音と BGM は自作の合成音(tool/build_sounds.dart)。iOS では消音スイッチに従い、ほかのアプリの音楽を止めない | 正式な音素材に替えるときは assets/sounds/ の wav を差し替える |
| A17 | セーブデータは 1 つのキーに JSON でまとめて保存。読めないデータは別のキーへ退避して最初から始める | 退避したデータは、問い合わせがあったときに調べられる |
| A18 | プライバシーポリシーと利用規約は、アプリ内に「案」として表示 | 公開前に内容を確定し、Web にも公開する |
| A19 | 最初から持っている列車・駅舎・駅長さんも、図鑑で最初は NEW と表示する | 図鑑を開くきっかけにするため |
| A20 | 星の合計は「各ステージの最高の星」の合計 | 再挑戦で下がらない |
