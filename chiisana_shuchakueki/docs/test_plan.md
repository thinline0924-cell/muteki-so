# テスト計画

## 1. テストの動かし方

```
cd chiisana_shuchakueki
flutter analyze      # コードの書き方のチェック
flutter test         # 自動テストをすべて実行
```

GitHub に push すると、GitHub Actions(GitHub 上で自動でコマンドを動かすしくみ)が同じ
テストを実行し、Android の APK も作ります(`.github/workflows/chiisana_shuchakueki.yml`)。

## 2. テストの一覧と状況

○ = 自動テストあり、△ = 一部、— = 未実装(その機能がまだない)

### 2.1 パズルロジック(test/puzzle/)

| 要件 | 状況 | テスト |
|---|---|---|
| 線路タイルが 90 度回転する | ○ | tile_test「タップ 1 回で 90 度回り…」 |
| 回転後の接続方向が正しい | ○ | tile_test「直線の接続」「カーブの接続」「T字は 3 方向」 |
| 接続した線路だけを列車が通過できる | ○ | route_test「つながった線路を通って…」 |
| 接続していない線路で列車が停止する | ○ | route_test「つながっていない線路の手前で止まる」 |
| 目的地へ到着するとクリア | ○ | route_test, session_test「解いて出発するとクリア」 |
| 目的地へ到着できない場合は失敗 | ○ | route_test「線路のないマス」「目的地に反対側から」「出発駅に突っこむ」 |
| 盤面外への移動を検出 | ○ | route_test「盤面の外へ出ると失敗」 |
| ループを検出 | ○ | route_test「ぐるぐる回るループ」+「十字を 2 回通ってもループ扱いしない」 |
| 不正なステージデータを検出 | ○ | stage_format_test(駅の欠落・重複・外向き、サイズ不一致、記号、星、報酬、id) |
| 不正な盤面でクラッシュしない | ○ | route_test「出発駅や目的地がない盤面は…」、stage_format_test「ステージ集…クラッシュしない」 |
| 操作を取り消すと盤面が正しく戻る | ○ | session_test「1手戻すと盤面と手数が元に戻る」 |
| リセットが正しく動作する | ○ | session_test「リセットで最初の盤面と手数 0 に戻る」 |
| 走行中は操作できない | ○ | session_test「走行中は回す・戻す・リセット・再出発ができない」 |
| 星の評価 | ○ | session_test「星の評価」 |
| ソルバーとヒント | ○ | solver_test |
| クリア済みの最高評価が維持される | ○ | game/progress_test「再挑戦で悪い結果でも…下がらない」 |
